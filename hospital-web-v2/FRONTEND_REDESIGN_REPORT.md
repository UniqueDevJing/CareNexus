# CareNexus 前端重构记录

## 产品方向

- **产品**：面向患者的就诊准备智能体，在一次对话里整理症状、识别风险、给出下一步，并在必要时把任务交给医护人员。
- **性格**：克制、准确、带一点温度。
- **视觉世界**：安静的门诊工作台，使用纸张、病历夹和夜班值守的深墨绿色作为隐喻。
- **视觉重点**：患者对话面板与“下一步”决策卡；其他区域保持低对比度，避免信息竞争。
- **签名细节**：每一步都以“下一步行动”结尾，而不是展示无法执行的模型结论。

## 本次改造

- 将主导航从后台模块目录收拢为患者智能体、就诊记录、费用与预约三个入口。
- 医生、护士、运营端只保留队列、接诊和运行观测入口，原有配置路由保留为兼容入口但不再作为主流程展示。
- 统一色彩、间距、圆角、按钮和状态表达；去除背景纹理、装饰性渐变和无意义的发光元素。
- 将患者端的状态词典和快捷描述抽取到 `src/config/clinical.js`，导航定义抽取到 `src/config/navigation.js`。
- 登录页改为患者优先，明确说明医护只在需要人工判断时接手。
- 更新页面元信息、生产标题和描述，避免继续以“医院管理后台”作为产品第一印象。

## 三轮审美评估

### 第一轮：结构与信息层级

- 检查登录页、患者主流程和移动端首屏。
- 结果：患者对话区成为最大视觉主体；步骤、隐私边界和人工接手说明均能在首屏找到；390px 无横向溢出。

### 第二轮：视觉系统与交互

- 检查登录/注册切换、快捷症状填入、发送按钮状态和患者侧栏信息密度。
- 结果：登录页不再把四类角色平均展示；快捷症状能填入输入框并正确启用发送；按钮、边框和状态颜色统一。

### 第三轮：角色一致性与响应式

- 检查运营概览桌面端与移动端，并对患者端再次复核。
- 结果：后台入口保持同一套视觉语法，运营页面在 1280px 与 390px 下无重叠、无横向滚动；移动端导航可打开、关闭并保持焦点路径。

## 验证结果

- `npm run build`：通过。
- Playwright 真实浏览器检查：登录页、患者端、运营端桌面/移动端截图通过。
- 真实后端联调：本轮未启动后端，浏览器中的 API 请求错误仅代表本地后端未运行，不能据此宣称业务链路已通过。
