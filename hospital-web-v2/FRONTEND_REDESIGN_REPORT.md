# CareNexus 前端重构记录

## 产品方向

- **产品**：面向患者的就诊准备智能体，在一次对话里整理症状、识别风险、给出下一步，并在必要时把任务交给医护人员。
- **性格**：克制、准确、带一点温度。
- **视觉世界**：安静的门诊工作台，使用纸张、病历夹和夜班值守的深墨绿色作为隐喻。
- **视觉重点**：患者对话面板与“下一步”决策卡；其他区域保持低对比度，避免信息竞争。
- **签名细节**：每一步都以“下一步行动”结尾，而不是展示无法执行的模型结论。

## 本次改造

- 将患者导航补全为智能导诊、就诊记录、费用与预约、检查结果、处方五个真实入口。
- 将医生、护士和管理端的真实路由重新按临床工作、人工处理、运行概览、临床数据和智能体配置分组展示，避免产品看起来只有患者端。
- 采用“临床指挥板”视觉方向：中性灰绿底、深墨蓝文字、单一青绿色行动色，统一色彩、间距、圆角、按钮和状态表达。
- 预问诊完成态不再锁死输入框；发送新内容会自动创建新的会话，同时保留上一轮记录与预约结果。
- 去除背景纹理、装饰性渐变和无意义的发光元素，压缩导航密度并保留 375px、768px、1280px 的响应式断点。
- 将患者端的状态词典和快捷描述抽取到 `src/config/clinical.js`，导航定义抽取到 `src/config/navigation.js`。
- 登录页改为患者优先，明确说明医护只在需要人工判断时接手。
- 更新页面元信息、生产标题和描述，避免继续以“医院管理后台”作为产品第一印象。

## 三轮审美评估

### 第一轮：结构与信息层级

- 检查登录页、患者主流程、角色导航和移动端首屏。
- 结果：患者对话区成为最大视觉主体；步骤、隐私边界和人工接手说明均能在首屏找到；390px 无横向溢出。

### 第二轮：视觉系统与交互

- 检查登录/注册切换、快捷症状填入、完成态继续输入、发送按钮状态和患者侧栏信息密度。
- 结果：完成态输入框保持可编辑，输入新问题后按钮启用并创建新会话；快捷症状能填入输入框并正确启用发送；按钮、边框和状态颜色统一。

### 第三轮：角色一致性与响应式

- 检查患者、护士、医生、运营四类角色的真实登录与入口，以及患者端再次复核。
- 结果：四类角色均能进入各自工作台；运营端可见完整配置、知识库、工具日志和执行记录；移动端导航可打开、关闭并保持焦点路径。

## 验证结果

- `npm run build`：通过（Vite 生产构建）。
- Playwright 真实浏览器检查：患者三轮对话、完成态继续输入并自动新建会话、患者/护士/医生/运营登录入口通过。
- 本轮浏览器使用本地 Spring Boot 后端联调；未执行生产推送，需在用户授权后再部署。
