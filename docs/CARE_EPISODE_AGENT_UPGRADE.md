# CareNexus 门诊任务智能体升级方案

## 产品边界

CareNexus 聚焦一次真实的普通门诊就医过程：患者描述问题、完成安全分流、选择号源、到院签到、医生接诊、检查/处方、报告回诊、诊后提醒。系统不承担诊断、处方签发或急危重症处置决定；这些动作由规则和具备资质的医务人员完成。

## 现实业务依据

- 国家卫生健康相关公开流程覆盖智能导诊、预约、提醒、签到、候诊、病史授权、检查预约、支付、报告、取药、用药提醒和随访。
- 门诊的真实闭环不是“分诊完成”，而是围绕一次就医任务持续推进，检查结果返回后还可能回诊。
- “一次挂号管一次就医流程”说明同一疾病的初诊、检查和回诊应保持同一就医上下文。

## 目标架构

```text
患者输入
  -> 就诊任务（care_episode）
  -> Agent 规划与工具调用
  -> 安全规则 / 证据校验
  -> 预约、签到、接诊、医嘱、报告、随访
  -> 下一步任务或医生接管
```

人工复核保留为一种能力，不再作为独立护士产品端。医生工作台消费高风险、低置信度、信息冲突和报告异常任务。

## 核心状态

`INTAKE -> TRIAGED -> SLOT_PROPOSED -> WAITING_CONFIRMATION -> BOOKED -> CHECKED_IN -> WAITING_DOCTOR -> IN_CONSULTATION -> ORDERS_PENDING -> WAITING_RESULTS -> NEEDS_REVIEW -> COMPLETED -> FOLLOW_UP`

高风险分支：`RISK_DETECTED -> EMERGENCY_GUIDANCE -> HUMAN_ESCALATION`。

状态只能由服务端根据允许的前置状态推进，所有推进写入事件表并保留操作者、来源和幂等键。

## 本轮实现范围

1. 建立 `care_episode`、`care_episode_event` 和 `agent_task` 数据底座。
2. 让患者会话、分诊建议和预约关联到同一就医任务。
3. 提供当前任务、时间线和下一步动作接口。
4. 将人工复核文案和状态统一为“临床接管”，不再把护士作为产品主角色。
5. 患者端展示任务时间线与真实下一步，避免“推荐科室”和“可预约”混为一谈。
6. 增加状态机、幂等、越权和异常恢复测试。

## 不做的事情

- 不伪造医保、支付、电子健康卡或真实医院 HIS 集成。
- 不让模型自主诊断、开药或绕过医生确认。
- 不为了展示而增加住院、药房、体检等未打通的模块。

## 质检轮次

1. 基线与依赖检查
2. 数据模型与状态不变量
3. Agent 工具与安全边界
4. 患者端任务恢复
5. 医生端人工接管
6. 异常、幂等和并发
7. 前端视觉与可访问性
8. 构建、集成、浏览器和生产冒烟

每一轮必须记录命令、结果和未验证项；没有运行证据的结论标记为 `UNVERIFIED`。
