# CareNexus｜基于 LangChain4j + Spring Boot 的智能分诊就医系统

CareNexus 是一个面向门诊服务的患者智能体。患者只需要描述当前不适，系统就会逐步补齐必要信息、识别需要优先处理的风险、匹配可用就诊资源，并在不确定时把任务交给医生工作台进行临床确认。

它不是一个只负责聊天的页面，而是一条可以落库、追踪和复核的就诊协同链路：

```text
患者描述 → 智能追问 → 风险分层 → 科室/医生匹配 → 号源确认 → 医生接诊 → 结构化病历
```

## 项目解决的问题

传统就医系统通常把挂号、问诊、病历和运营数据拆在不同页面，患者不知道下一步该做什么，医护也需要重复整理信息。CareNexus 将这几个环节收敛为一条有状态的就诊流程：

- 患者用自然语言描述问题，系统通过多轮追问整理症状、时间、严重程度和健康背景。
- 命中胸痛、呼吸困难、意识异常等高风险征象时，先执行确定性安全规则，优先提示急诊或人工处理。
- 风险可控且信息足够时，查询真实科室、医生排班和号源，患者确认后再提交预约。
- 低置信度、号源异常、工具失败或模型未收敛时，自动生成临床接管任务，不把不确定结果直接写成预约或诊断。
- 医生在接诊台查看患者授权范围内的资料，完成结构化病历并提交归档。

## 核心能力

### 患者智能体

- 注册、登录、会话恢复和健康档案维护。
- 多轮预问诊、上下文记忆和 SSE 流式回复。
- 红旗征象识别、风险提示和就诊方向建议。
- 科室、医生、排班和可用号源查询。
- 预约确认、账单支付、就诊记录和结构化病历查看。

### 医护协同

- 医生工作台处理智能体无法安全确认的任务，可补问、确认或转人工服务，并直接进入接诊记录。
- 医生端查看候诊队列、患者背景和历史记录，填写并提交结构化病历。
- 患者与医生通过就医任务、事件和下一步动作关联，避免依靠页面刷新或手工复制信息。

### 运营与可追溯

- 科室、医生、排班、患者和基础数据维护。
- 模型配置、提示模板、医学知识资料和工具注册管理。
- Agent 执行时间线、工具调用日志、模型调用统计和异常原因记录。
- 人工处理、预约写入和病历提交均保留操作者、状态和时间信息。

## Agent 如何工作

CareNexus 将模型限制在受控的业务工具和状态机内，模型只负责理解和提出建议，服务端负责决定哪些结果可以进入业务状态。

1. **收集上下文**：读取本次会话、健康档案和授权范围内的历史就诊信息。
2. **补齐关键信息**：围绕症状部位、起始时间、严重程度和伴随征象进行有限轮次追问。
3. **执行安全规则**：高风险征象优先于模型建议，触发急诊或人工接手路径。
4. **调用业务工具**：查询科室、医生、排班和实时号源，返回结果后再进入下一步。
5. **输出可校验建议**：建议必须带有状态、依据、证据置信度和下一步动作。
6. **不确定时停止**：超过最大执行步数、工具失败、信息不足或模型异常时，生成待人工处理任务，禁止直接预约。

每次就诊都有独立的 `care_episode`。它保存当前状态、下一步任务和事件时间线，患者刷新页面后可以恢复上下文，医生工作台也能看到同一条接管任务。

关键业务写入全部由服务端完成权限校验、患者归属校验、状态校验和事务控制；模型不能直接修改号源、预约、账单或病历。

## 关键数据链路

```text
会话消息
  └─> Agent 状态与执行记录
        ├─> 风险规则与分诊建议
        ├─> 科室/医生/号源查询
        ├─> 临床接管任务
        └─> 预约、支付、接诊和病历记录
```

预约提交时，服务端会重新检查患者身份、建议状态、医生归属、号源余量和重复预约，并在同一事务中完成号源扣减与预约写入，避免前端展示的号源与最终数据不一致。

## 技术栈

| 层次 | 技术 |
| --- | --- |
| 后端 | Java 21、Spring Boot 3.5、Spring Security、Spring JDBC |

| 前端 | Vue 3、Vite、Vue Router、Element Plus、GSAP |

## 本地运行

### 1. 准备环境

- Java 21
- Maven 3.9+
- Node.js 20+
- MySQL 8（本地开发可先使用默认 H2）

复制根目录 `.env.example`，按实际环境配置数据库、认证密钥和模型参数。不要把 `.env` 或任何密钥提交到 Git。

### 2. 启动后端

```bash
cd hospital-v2
mvn test
mvn spring-boot:run
```

后端默认监听 `18092`，接口前缀为 `/v2/api`。健康检查：

```bash
curl http://127.0.0.1:18092/v2/api/health
```

### 3. 启动前端

```bash
cd hospital-web-v2
npm ci
npm run dev
```

默认入口：<http://127.0.0.1:5192/CareNexus/>。

如果后端不在默认地址，可通过环境变量指定前端开发代理：

```powershell
$env:V2_BACKEND = "http://127.0.0.1:18092"
npm run dev -- --host 127.0.0.1 --port 5192
```

## 部署

生产前端入口为 `/CareNexus/`，后端通过 Nginx 反向代理到 `/v2/api/`。完整部署步骤见 [`deploy/部署指南.md`](deploy/部署指南.md)。

非容器构建：

```bash
cd hospital-v2
mvn -B clean package -DskipTests
cd ../hospital-web-v2
npm ci && npm run build
```

生产环境必须使用随机 JWT 密钥、独立数据库账号和模型密钥；如果外部入口仍为 HTTP，认证 Cookie 不应错误配置为 `Secure`。正式上线前应在网关层启用 HTTPS，并重新核对 Cookie、安全响应头、日志脱敏和数据库备份策略。

## 安全边界

- 患者只能读取自己的会话、预约、账单和就诊记录。
- 临床接管任务只能由有权限的医生工作台确认，不能绕过状态机直接预约。
- 医生只能接诊分配给自己的患者，提交后的病历不能被普通请求覆盖。
- 管理员可查看运营和审计数据，但敏感字段不会在接口中明文回显。
- 医疗建议仅用于就诊准备和决策支持，不替代医生诊断；出现危急症状应立即线下就医。
